# Archived configurations

Superseded on 2026-09-29, when twelve presets across two separate catalogues
(`design.py` and `highfidelity/configs.py`) were collapsed to four in one place.

**These files still work.** They are kept here so nothing is lost and so the
capability trade-off is documented rather than assumed. Pass one with `--cfg` like
any other. They are *not* regenerated by
`highfidelity.configs --all`, so if you edit one it stays edited.

Nothing became unreproducible by archiving them: `live.py` copies the exact `.cfg`
it sent into every run directory, and all 37 existing runs carry theirs.

---

## What we actually lost

Five of the nine are **exact duplicates** of an active preset — same geometry,
same frame rate, same payloads. These were renames, not losses:

| archived | identical active preset |
|---|---|
| `microdoppler-fast` | `gait` (128×64, 25 fps, no payload) |
| `angle-ghost` | `ghost` (128×128, 10 fps, TLV 8) |
| `empty-room` | `ghost` — it was a parameter-identical copy; "empty room" is a capture protocol, now `--label empty-room` |
| `rdmap-balanced` | `doppler` (64×64, 8 fps, TLV 5) |
| `both-survey` | `survey` (64×64, 5 fps, TLV 5 + 8) |

Four represent a **genuine capability the four active presets do not cover**:

### 1. `limb-separation` — 128 Doppler bins at 20 fps, no heat map

The real gap. Highest time × velocity-resolution product available, and cheap on
the link (12%).

| | `limb-separation` | nearest active |
|---|---|---|
| Doppler bins | 128 (0.0635 m/s) | `ghost`: 128 — but at **10 fps** |
| frame rate | **20 fps** | `gait`: 25 fps — but only **64** bins (0.127 m/s) |
| payload | none | `ghost` spends 73% of the link on TLV 8 |

`ghost` has the same chirp geometry (96 loops → 128 zero-padded bins) but halves
the frame rate to afford TLV 8. So: **use this when you want the finest velocity
resolution AND high frame rate and do not need angle** — separating a hand from a
torso from a leg within one frame. True (CPI-limited) resolution is 0.0847 m/s,
since the 128-bin FFT is zero-padded from 96 chirps.

### 2. `rdmap-fast` — TLV 5 at 15.2 fps

The only fast dense range-Doppler option. `doppler` runs at 8 fps.

| | `rdmap-fast` | `doppler` |
|---|---|---|
| frame rate | **15.2 fps** | 8 fps |
| Doppler bins | 32 (0.254 m/s) | 64 (0.127 m/s) |

It buys frame rate by halving Doppler bins; both sit at ~75% of the link. **Use it
when you want a Tier-B dense VT map of something moving** and can accept coarse
velocity bins. `doppler` is the better choice for a static scene.

### 3. `microdoppler-fine` — 128 bins at 10 fps, no heat map

Strictly dominated by `limb-separation` (same geometry, half the frame rate). Its
one distinction: the radar cube lands at **768 KB, exactly the L3 limit**, so it is
the preset most likely to be rejected by the device — useful only as a memory-limit
test case.

### 4. `microdoppler` — `gait` at 10 fps instead of 25

Identical radar processing to `gait`; only the frame period differs. Duty cycle
drops from 48% to 19%, so **use it for long captures where self-heating matters**
(the temperature TLV will tell you). Otherwise `gait` is strictly better.

## Also never materialised as a `.cfg`

Two `design.py` presets were definitions only and never written to this directory.
Recording them here because one covers a real gap:

* **`balanced`** — 256 range bins (**0.0436 m**, the finest available) at 32
  Doppler bins, ±2.02 m/s, 10 fps. **No active preset has 256 range bins with a
  usable velocity span.** `ti-baseline` has 256 bins but aliases at ±0.97 m/s.
  Regenerate from `ChirpDesign(num_adc_samples=256, num_loops=32,
  idle_time_us=143, ramp_end_time_us=57.14, frame_periodicity_ms=100)` if fine
  range resolution ever matters more than Doppler.
* **`baseline`** — the TI `best_range_res` equivalent, i.e. the same design as
  `../xwr68xx_AOP_ti-baseline_10fps_points.cfg`, which is kept as a verbatim TI
  export instead.

## `angle-probe` is deliberately *not* archived

It was a 5 fps, 32-Doppler-bin **diagnostic**, written to measure the real TLV 8
payload size once and then be replaced. It never was: every experimental capture on
2026-09-26 — the foam-wall, drywall and two-subject runs — used it. At 5 fps that
is roughly 5 samples per stride, which is why the gait metrics from that session
are not trustworthy. It is a Nyquist problem in the data; no analysis code repairs
it, and those runs need recapturing with `gait` or `ghost`.

It has been **deleted rather than archived** so it cannot be picked again. Its job
is complete: the TLV 8 payload is **3072 bytes** at 64 range bins =
`4 × 12 virtual ant × 64`, decoding to a `(64, 12) complex64` array with zero parse
anomalies — exactly the inferred size, so the worry that a 2× payload would push a
full-resolution angle config to 139% of the UART is settled.

The 21 runs captured with it still parse correctly and their angle figures are
valid. Only the *frame rate* was wrong. Each one carries its own `.cfg`, so they
remain fully reproducible.
